# Finishing Framework

A framework for helping you complete projects. The problem isn't starting - it's finishing.

## Core Principle

**Ship imperfect things.** Done is better than perfect. Technology accelerates fast — waiting for perfect means waiting forever.

## The Finishing Questions

When evaluating any project, ask:

### 1. What's the Smallest Shippable Piece?

Break the project down until you find something that can be:
- Completed in one focused session (2-3 hours max)
- Released/shared/published in some form
- Marked as DONE

Examples:
- A writing anthology: One story, not the whole collection
- An app: One user flow, not the whole product
- A framework: One essay, not the whole system

### 2. What's the Single Next Action?

Not a category of actions. ONE specific thing:
- "Write the opening paragraph of story X"
- "Create the database schema for Y"
- "Draft the post about Z"

If you can't name the single next action, the project isn't defined well enough.

### 3. What Would "Good Enough" Look Like?

Define the minimum viable version:
- What could be cut and still have something valuable?
- What's the 80/20 version?
- What would you ship if you only had one day?

### 4. Is This Actually Stuck?

Signs of a stuck project:
- No progress in 2+ weeks
- Repeated "I should work on X" without action
- Blocked on external input that hasn't come
- Scope creep making it feel overwhelming

If stuck, ask: **Archive, deprioritize, or push through?**

## Unsticking Strategies

### If overwhelmed by scope:
- List everything the project "needs"
- Cross out 50% of it
- Cross out another 50%
- What's left is your MVP

### If blocked on external input:
- Can you work around it?
- Can you make a decision and move forward?
- Set a deadline: "If I don't hear back by X, I'll assume Y"

### If you've lost interest:
- Is it still aligned with your goals?
- Can someone else finish it?
- Archive it guilt-free - not everything needs to be finished

### If perfectionism is blocking:
- Remember: You can iterate after shipping
- First version is for learning, not legacy
- "Ship something and see what happens"

## Project Health Check Template

```
Project: [NAME]
Last touched: [DATE]
Current state: [Brief description]

Smallest shippable piece: [ONE THING]
Single next action: [ONE ACTION]
Good enough would be: [MINIMUM VIABLE]

Stuck? [Yes/No]
If yes, why: [REASON]
Unsticking strategy: [APPROACH]
```

## The Accountability Question

Ask periodically: "What did you ship this week?"

Not "what did you work on" - what did you **ship**?

If the answer is consistently "nothing" for a project, it's time to either:
1. Make it the priority and ship something
2. Archive it and stop pretending

## Philosophy

The age of the idea person is here. But ideas without execution are worthless. The system should help turn ideas into shipped things - not accumulate more ideas.

You may have years of captured thinking. The bottleneck isn't ideas - it's finishing.
